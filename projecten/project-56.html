Project 56: Whack-a-Mole

Intermediate

Bouw deze razendsnelle arcade klassieker en leer krachtige concepten zoals recursie, pseudo-randomness, en event security.

📚 Wat ga je leren?

In dit project ligt de nadruk op asynchrone patronen en visuele manipulatie via klassen:

  • Recursie timing: Een functie die zichzelf aanroept, maar niet eindeloos vastloopt omdat er een setTimeout pauze tussen zit.
  • DOM Animaties: Het koppelen van JavaScript acties (elementen updaten) aan CSS transities.
  • Anti-Cheating Logica: Hoe voorkom je dat spelers JavaScript console commando's gebruiken om een highscore te halen?

🎯 Kernconcepten

  • Event.isTrusted: Een read-only eigenschap op een Event-object in de browser. Dit is true als de actie (zoals klikken) door een échte gebruiker is gedaan, en false als het via code zoals element.click() is getriggerd.
  • Closure Memory: Het opslaan van de lastHole zodat een mol niet twee keer na elkaar uit uit exact hetzelfde gat verschijnt.
  • CSS Overflow-Hidden: De mollen zijn altijd aanwezig op de pagina, ze bevinden zich alleen fysiek "onder" de rand van het gat. overflow: hidden knipt alles af wat buiten de 'hole' valt.

📝 Stap-voor-Stap Uitleg

Stap 1: Unieke Random Gaten

We willen dat een mol overal kan opduiken, behalve uit het gat waar hij zojuist in verdween.

function randomHole() {
    let idx;
    do {
        idx = Math.floor(Math.random() * mollen.length);
    } while (idx === lastHoleIdx); // Blijf zoeken tot we een nieuwe hebben
    
    lastHoleIdx = idx;
    return mollen[idx];
}

Uitleg: De do...while loop is hier perfect: hij voert de code altijd minstens één keer uit en controleert pas achteraf of de conditie is gebroken.

Stap 2: De Asynchrone Recursie Loop

In plaats van een vast interval, gebruiken we recursie om variatie te creëren.

function popMole() {
    if (!gameActive) return;
    const time = randomTime(600, 1200);
    
    hole.classList.add('show'); // Mol omhoog
    
    setTimeout(() => {
        hole.classList.remove('show'); // Mol omlaag
        if (gameActive) popMole(); // Start cyclus opnieuw
    }, time);
}

Uitleg: Telkens als deze functie wordt aangeroepen, pauzeert deze zichzelf met setTimeout op een willekeurige tijd. Als de tijd om is, wordt de mol verborgen en dan triggert de functie zichzelf opnieuw. Zonder de if (gameActive) check zou dit voor eeuwig doorgaan!

Stap 3: Slaan en Score Bijhouden

We moeten detecteren of de klik authentiek is.

function whack(e) {
    if (!e.isTrusted) return; // Cheater!
    if (!this.classList.contains('show')) return;

    score++;
    this.classList.remove('show');
}

Uitleg: Zonder de contains('show') veiligheidscheck zouden snelle spelers twee keer op de mol kunnen slaan terwijl hij met zijn omlaag-animatie bezig is, en beide punten kunnen innen.

⚠️ Veelvoorkomende Fouten

Fout: Event bubbling missers

Omdat mollen over elkaar heen kunnen renderen (of over hun hole-wrapper), klikken gebruikers per ongeluk soms op de parent-container in plaats van op de mol. Oplossing is om een "Event Listener" op de parent te zetten óf, beter, CSS pointer-events: none te zetten op elementen die nooit geklikt mogen voelen.

Fout: Recursieve lawine (Stack overflow)

Als je de setTimeout vergeet rond de recursieve aanroep (popMole();), loopt de browser onmiddellijk vast omdat de functie tienduizenden keren in een fractie van een seconde wordt gestart.

💡 Tips voor Studenten

  • Timing finetunen: Pas de `randomTime(600, 1200)` aan. Een tijd tussen 300 en 800 maakt het spel drastisch moeilijker.
  • Visuele feedback: Wij hebben hier de .hit-anim klasse toegevoegd, wat aantoont hoe visuele "klappen" (een rode flash) enorm helpen voor de feel van een arcade game.

🚀 Uitbreidingsmogelijkheden

  • Decoy (bom) Mollen: Maak 10% kans dat een gepopte mol rood / agressief uitziet. Raak je die, verlies je 2 punten!
  • Versnellende timer: Zorg dat de gemiddelde pauze tussen het verschijnen van mollen korter wordt naarmate de interne gametijd nadert (bijvoorbeeld als er nog maar 5 seconden is, dat ze razendsnel opkomen).

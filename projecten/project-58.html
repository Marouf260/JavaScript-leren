Project 58: Flappy Bird

Advanced

Maak de iconische Flappy Bird kloon en duik in de wereld van game-physics. Leer hoe je zwaartekracht, objectpools en AABB-botsingsdetectie implementeert.

📚 Wat ga je leren?

Dit spel is essentieel voor elke web developer die met animaties wil werken. Het leert je:

  • The Game Loop: Hoe requestAnimationFrame zorgt voor boterzachte 60 FPS in plaats van schokkerige setInterval rendering.
  • Basis Physics: Werken met "velocity" (snelheid) en "gravity" (versnelling). Hoe beïnvloedt zwaartekracht de valsnelheid exponentieel?
  • Hitbox Berekningen (AABB): Axis-Aligned Bounding Box collision. Hoe reken je razendsnel uit of twee vierhoeken elkaar overlappen?

🎯 Kernconcepten

  • Velocity (Snelheid): Beheert de verplaatsing op de y-as. Bij het 'flappen' wordt deze instant op een negatieve waarde gezet (-7px/frame), en daarna duwt de zwaartekracht dit elke frame langzamerhand naar een positieve (vallende) waarde.
  • Garbage Collection / Memory Leaks: We blijven buizen oneindig toevoegen. Als we oude buizen (die links uit beeld verdwijnen) niet zouden verwijderen (element.remove()), stijgt het geheugengebruik totdat de browser crasht.
  • getBoundingClientRect(): Een extreem handige ingebouwde JS-functie die precies teruggeeft waar op het scherm een element zich bevindt en hoe groot het is (top, bottom, left, right).

📝 Stap-voor-Stap Uitleg

Stap 1: Zwaartekracht & Simulatie

Bij elke frame (tick) wordt de zwaartekracht bij de snelheid opgeteld, waarna de vogel verplaatst wordt op basis van die snelheid.

function loop() {
    velocity += GRAVITY;   // Snelheid neemt elke frame toe
    birdY += velocity;     // Vogel valt steeds sneller
    bird.style.top = birdY + 'px';
    
    // Herhaal dit 60x per seconde
    requestAnimationFrame(loop); 
}

Uitleg: Dit is de hartslag van elke physics engine. Omdat velocity continue door de zwaartekracht toeneemt, remt een opwaartse 'flap' vanzelf langzaam af en resulteert dan weer in een val.

Stap 2: procedurele Generatie

De opening tussen buizen moet altijd op een willekeurige hoogte (top) voorkomen.

// topH is willekeurig ergens tussen 50px en 250px
const topH = Math.random() * 200 + 50;

top.style.height = topH + 'px';
bottom.style.height = (400 - topH - GAP) + 'px';

Uitleg: Hoe lang moet de onderste buis zijn? Totale veld (400) minus (-) Lengte van de Bovenste Buis (-) Vaste Tussenruimte (GAP).

Stap 3: Collision Check Logica (AABB)

Dit is één van de beroemdste logica blokjes in game dev.

function isColliding(r1, r2) {
    return !(
        r1.right < r2.left ||  // r1 is volledig links van r2
        r1.left > r2.right ||  // r1 is volledig rechts van r2
        r1.bottom < r2.top ||  // r1 is volledig boven r2
        r1.top > r2.bottom     // r1 is volledig onder r2
    );
}

Uitleg: De code draait de logica om. Het vraagt "Wanneer overlappen ze *NIET*?". Ze overlappen *niet* als rechthoek 1 (r1) helemaal aan één van de vier zijdes verwijderd is van rechthoek 2 (r2). Het omgekeerde hiervan is automatisch een hit!

⚠️ Veelvoorkomende Fouten

Fout: setInterval in plaats van rAF()

setInterval(() => loop, 16) probeert te tekenen ook al is je scherm (monitor) daar fysiek nog niet aan toe. Dit veroorzaakt 'screen tearing' of stotters. requestAnimationFrame(loop) wacht braaf op de refresh cyclus van de monitor, wat het perfect vloeiend maakt.

Fout: CSS Transitions vs rAF

We hebben de CSS transition van de vogel moeten verwijderen. Als je de top-waarde of transform aanstuurt 60x per seconde in JavaScript, zal een CSS-transition hier alleen maar wazigheid ("trailing") of een laggy reactie aan toevoegen.

💡 Tips voor Studenten

  • Hitbox Tweak: Het vierkante gebied getBoundingClientRect() sluit een ronde div in. Hierdoor raak je de buis sneller (hoek tegen hoek). Je kunt dit finetunen door een kunstmatige marge te accepteren: `r1.right - 5 < r2.left`.
  • Input Handling: Onthoud dat de spatiebalk van nature webpagina's omlaag laat scrollen. We vangen dit specifiek af met e.preventDefault()!

🚀 Uitbreidingsmogelijkheden

  • Variabel "GAP": Hoe score stijgt, hoe kleiner het gat (GAP) tussen de groene buizen wordt. Laat het starten op 150px en eindigen op 90px (het hard-cap minimum).
  • Muntjes: Voeg als derde pipe element nog een div in (midden in het gap), die je weghaalt als de speler erdoorheen vliegt en 5 bonuspunten telt!

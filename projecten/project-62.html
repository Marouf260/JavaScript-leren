Project 62: Live Markdown Previewer

Advanced Interfaces

Bouw een live editor voor Markdown. Gebruik externe bibliotheken (CDN's) om complexe parsing en security layers met minimale eigen code op te zetten.

📚 Wat ga je leren?

Dit project vormt de brug tussen eenvoudige DOM manipulatie en het bouwen van productierijpe web applicaties. Je leert:

  • CDN Integratie: Het koppelen van externe JavaScript libraries (zoals Marked en DOMPurify) om de 'zware' logica off-the-shelf te importeren.
  • Realtime Parsing: Het luisteren naar input events voor "live" character updates, zonder de performance te vernietigen.
  • Security (XSS Defensie): Het beveiligen van je render-engine tegen Cross-Site Scripting. Nooit blind ongefilterde user-input via innerHTML renderen!

🎯 Kernconcepten

  • Markdown Parsing: Omzetten van structurele symbols (zoals **bold** of # Kop) in browser-native HTML tags (zoals <b> en <h1>) noemen we "parsing".
  • Sanitization (Opschonen): Als we alleen Marked.js zouden gebruiken, kan een gebruiker <script>alert('Hacked!');</script> typen, wat onmiddellijk in de preview window zou openen en runnen! DOMPurify filtert dit virus eruit.
  • Clipboard API: Met navigator.clipboard.writeText(...) geven we de gebruiker de mogelijkheid the opgeschrapte, veilige HTML-versie naar hun eigen klembord te kopiëren.

📝 Stap-voor-Stap Uitleg

Stap 1: Libraries Laden (De Head)

We hebben twee helpersb nodig: Marked (vertaalt MD → HTML) en DOMPurify (Maakt gevaarlijke HTML → Veilige HTML).

<script src="https://.../marked.min.js"></script>
<script src="https://.../purify.min.js"></script>

Stap 2: Input vs HTML Output

Bij elke kleine toetsaanslag halen we de raw string op en douwen die door onze 'pijpleiding'.

function updatePreview() {
    // 1. Haal Ruwe Data (MarkDown formulier)
    const rawHtml = marked.parse(editor.value);
    
    // 2. Zuiver Alle Evil Code eruit! Let the good stuff pass.
    const cleanHtml = DOMPurify.sanitize(rawHtml);
    
    // 3. Toon het in de Browser
    preview.innerHTML = cleanHtml;
}

Stap 3: CSS voor de Output Vrezen

Omdat we ineens <h1>, <pre>, en <code> elementen direct in onze preview box forceren, moeten we in onze CSS stylesheet specifiek styles definiëren voor elementen "inside" de .preview-area. Anders zien ze er rauw uit.

⚠️ Veelvoorkomende Fouten

Fout: Geen Sanitization (Beveiligingslek)

Omdat Marked.js tegenwoordig by-default weigert om te "sanitizen" (omdat dat niet de taak is van een markdown parser), betekent dit dat jouw website direct kwetsbaar is voor XSS-hacks als je DOMPurify weglaat en in productie gaat.

Fout: Input vs Change vs Keyup event

Veel studenten gebruiken keyup om updates te triggen, maar hierdoor voel je lag, én het vangt geen 'Copy-Paste' acties the vie het muismenu gaan! change vuurt pas als de editor unfocust. input is het absolute superieure event voot live textvelden.

💡 Tips voor Studenten

  • Event Debouncing: Heb je een gigantisch lang document waarbij elke letter typen the computer laat happeren? Wikkel dan je update functie in een setTimeout via een "Debounce" design pattern, zo voert de parser de berekening pas uit wanneer je 300 milliseconde "stopt" met typen!

🚀 Uitbreidingsmogelijkheden

  • File Extractor: Voer een "Download als .md" knop toe. Gebruik de Blob API (new Blob([editor.value], {type: "text/markdown"})) om The file force-to-download uit te voeren over de user browser!
  • Synchronized Scrolling: Scrollt de gebruiker paktweg naar regel 100 in de editor? Bereken via JavaScript the scroll percentage, en stuur de Preview Area óók qua scrollbar 50% naar beneden zodat de schermen synchroon blijven.

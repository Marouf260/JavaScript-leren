Pokédex Master

Parallel API Requests

Leer hoe je complexe datasets ophaalt met parallelle netwerkverzoeken. We bouwen een visuele database van de eerste 151 Pokémon met realtime zoekfunctionaliteit.

Pokémon worden uit het gras gehaald... 🔴

📚 Wat ga je leren?

Het bouwen van een Pokédex vereist meer dan één simpele fetch. Je leert hoe je massale hoeveelheden data efficiënt naar de browser haalt zonder vertraging.

  • Parallel Processing: Het gebruik van Promise.all() om 20 verzoeken tegelijk te sturen.
  • Dynamic Data Injection: Het omzetten van JSON-data naar complexe HTML-componenten.
  • Async Searching: Een zoekinterface bouwen die zowel IDs als namen begrijpt.

🎯 Kernconcepten

  • The Waterfall Effect: Waarom je niet één-voor-één API requests wilt doen (het is traag), maar "parallel" wilt gaan.
  • Higher Order Render Functions: Functies schrijven die elementen creëren op basis van een datastructuur.
  • API Rate Limiting: Inzicht in hoe je respectvol omgaat met publieke servers zoals PokeAPI.

📝 Stap-voor-stap: Parallelle Verzoeken

1: Het mandje volgooien

In plaats van te wachten op elke fetch, vullen we een Array met "Promises" (beloftes dat data komt). 

const promises = [];
for(let i=1; i<=20; i++) {
    promises.push(fetch(url + i).then(r => r.json()));
}
// Nu hebben we 20 verzoeken die 'onderweg' zijn.

2: Wachten op alles tegelijk

Met Promise.all() wacht JavaScript tot álle beloftes in het mandje zijn ingelost.

const pokemons = await Promise.all(promises);
// 'pokemons' is nu een array met 20 complete data objecten!

⚠️ Veelvoorkomende Fouten

  • Te veel Requests: Proberen 1000 Pokémon parallel te laden. Dit kan je browser (of de server) blokkeren. Doe het altijd in batches.
  • Asset Management: Gebruik de 'official-artwork' van de API; de standaard sprites zijn vaak erg klein en onscherp.

🚀 Uitbreidingen

  • Infinite Scroll: Laad de volgende 20 Pokémon zodra de gebruiker onderaan de lijst is.
  • Type Filtering: Voeg knoppen toe om alleen 'Fire' of 'Water' Pokémon te tonen.

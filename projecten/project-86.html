📚 Wat ga je leren?

Het meten van snelheid is essentieel voor een goede User Experience. De Performance API geeft je toegang tot de interne klok van de browser.

  • Network Timing: Het uitlezen van de navigation entry om te zien hoe lang de server erover deed.
  • High Resolution Timing: Waarom performance.now() tot op de microseconde nauwkeurig is.
  • Heavy Computations: Het timen van loops om de efficiëntie van je algoritmes te testen.

🎯 Kernconcepten

  • DOM Content Loaded: Het moment dat de HTML-structuur klaar is, maar afbeeldingen nog laden.
  • Full Load: Het moment dat alles (incl. CSS en zware images) op het scherm staat.
  • Performance Memory: Het in de gaten houden van het RAM-geheugen dat je tabblad verbruikt.

📝 Stap-voor-stap: De Meet-Logica

1: Browser Timing Uitlezen

We vragen de browser naar zijn 'navigation history' om te zien hoe lang het laden duurde.

const [nav] = performance.getEntriesByType('navigation');
const loadDuration = nav.loadEventEnd;

2: Handmatig Benchmarken

Door een start- en eindpunt vast te leggen, berekenen we de exacte verstreken tijd.

const t0 = performance.now();
doLaboriousTask();
const t1 = performance.now();
console.log(`Klaar in ${t1 - t0}ms`);

⚠️ Veelvoorkomende Fouten

  • Console.log Overhead: Loggen tijdens een benchmark vertraagt de test zelf aanzienlijk. Log pas ACHTERAF.
  • Browser Throttling: Als je CPU belast is (bv. door andere tabs), zal je test telkens een ander resultaat geven.
  • Cold Starts: JavaScript engines (V8) optimaliseren code tijdens het uitvoeren. Vaak is de tweede run sneller dan de eerste.

🚀 Uitbreidingen

  • Resource Timing: Meet specifiek hoe lang het duurde om een specifieke afbeelding of API-call op te halen.
  • Memory Limit: Gebruik performance.memory om te checken of je app tegen de geheugenlimiet aanloopt.
  • Custom Marks: Gebruik performance.mark() om belangrijke gebeurtenissen in de Chrome DevTools timeline te plotten.

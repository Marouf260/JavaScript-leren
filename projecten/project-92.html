📚 Wat ga je leren?

Het bouwen van een memory spel lijkt simpel, maar dwingt je om na te denken over 'race conditions'.

  • State Locking: Hoe je voorkomt dat een gebruiker 10 kaarten tegelijk omdraait.
  • 3D Transforms: Het gebruik van preserve-3d om een realistische flip te maken.
  • Array Shuffling: Het algoritme om kaarten elke keer willekeurig te verdelen.

🎯 Kernconcepten

  • Dataset Attributes: Het opslaan van data (welke emoji) direct in de HTML-node.
  • setTimeout() Management: Het beheren van de delay voordat kaarten weer terugdraaien bij een misser.
  • Truthiness: Controleren of firstCard al bestaat om de logica te splitsen.

📝 Stap-voor-stap: De Game Logic

1: Het Kaartenscreen Bouwen

We verdubbelen de emoji-lijst en schudden deze willekeurig.

const cards = [...emojis, ...emojis].sort(() => Math.random() - 0.5);

2: De Match Controle

Zodra twee kaarten zijn geklikt, vergelijken we de dataset waarden.

if (firstCard.dataset.emoji === secondCard.dataset.emoji) {
    // Het is een match!
    lockAndMarkMatched();
} else {
    // Geen match, draai terug na 1000ms
    setTimeout(unflip, 1000);
}

⚠️ Veelvoorkomende Fouten

  • Click Spamming: Gebruikers die heel snel klikken kunnen de logica breken. Gebruik een lockBoard boolean.
  • Self-match: Door op dezelfde kaart twee keer te klikken, zou het spel kunnen denken dat het een match is. Check op this === firstCard.
  • Memory Leaks: Het niet verwijderen van event listeners bij matched kaarten (optioneel, maar goed voor performance).

🚀 Uitbreidingen

  • Timer Mode: Voeg een countdown toe. Heb je alle paren binnen 30 seconden gevonden?
  • Grid Scaling: Laat de gebruiker kiezen tussen 4x4, 6x6 of zelfs 8x8 grids.
  • Thema's: Vervang emoji's door vlaggen, programmeer-logo's of foto's van huisdieren.
